# ЧистоДом — шаблон MVP выездной химчистки

Next.js + React + TypeScript + React Three Fiber + Drei + Prisma + PostgreSQL. Русский интерфейс, светлая/тёмная тема, калькулятор, корзина, заявки, приватная ссылка, кабинет владельца и PWA manifest.

## Запуск локально

1. Установить Node.js 20.9+.
2. `cp .env.example .env`, задать `SESSION_SECRET` (например, `openssl rand -base64 48`) и `DATABASE_URL`.
3. `docker compose up -d db`.
4. `npm install`.
5. Создать пароль администратора: `node -e "require('bcryptjs').hash('ВАШ_ПАРОЛЬ',12).then(console.log)"`, записать полученный хеш в `ADMIN_PASSWORD_HASH` в `.env`.
6. `npx prisma generate && npm run db:push && npm run db:seed`.
7. `npm run dev` и открыть http://localhost:3000. Для проверок: `npm run test`, `npm run typecheck`, `npm run build`.

Для production на пустой базе используйте `npm run db:migrate` вместо `db:push`, затем `npm run db:seed`. Не смешивайте `db:push` и `migrate deploy` на одной уже созданной базе без предварительного baseline.

## Формула

Для каждой известной позиции: `округление(базовая цена × (1 + процент сильного загрязнения + процент второй стороны матраса)) × количество`. Проценты суммируются от базовой цены, округление до целого рубля выполняется один раз на единицу. После суммирования применяется минимум заказа к чистке. Выезд за город прибавляется после минимума. «Другое» остаётся без цены до оценки; в смешанном заказе показывается известная сумма отдельно от ручной оценки. Сервер пересчитывает заказ по тарифам из БД и сохраняет снимок тарифов в заявке.

## Данные и безопасность

PostgreSQL — постоянное хранилище. Приватные фото в dev записываются в `UPLOAD_DIR` с непредсказуемыми именами; выдаются только по приватному токену заказа или сессии администратора. Заказ хранит только хеш токена. Идемпотентный ключ создаётся браузером и серверно преобразуется в детерминированный приватный токен через HMAC, повтор с тем же ключом возвращает ту же ссылку. Публичный API не отдаёт внутренние заметки.

**Перед production:** настройте приватный S3-compatible bucket (S3/R2) через `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT` и учётные данные; сервер загружает/отдаёт/удаляет фото через API и не выдаёт публичные URL. В production приложение откажется сохранять фотографии без `S3_BUCKET`. Upload endpoint принимает до 26 МБ на весь multipart-запрос; если лимит выбранной serverless-платформы ниже, потребуется отдельный flow прямой загрузки в S3 по presigned URL. Настройте Upstash Redis (`UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`) для общего rate-limit; используйте managed PostgreSQL с бэкапами; задайте `APP_URL`, `SESSION_SECRET`, `ADMIN_PASSWORD_HASH`; настройте HTTPS, CSP, мониторинг и ротацию секретов. Файловая система serverless не является постоянным хранилищем. Не запускайте production с локальным диском для фото.

## Ограничения текущей версии

- Процедурная настоящая геометрия Three.js вместо скачанных внешних GLB; лицензии сторонних моделей не нужны. Размерные варианты меняют цену/подпись, а не геометрию.
- Нет .blend: Blender/bpy недоступен в среде.
- Нет Figma файла: Figma MCP недоступен.
- Нет реальной игры по UV/raycast, персонажей с лицами, моргания или бонусного кода; настройки режима игры сохранены, применение бонуса не реализовано. Нет SMS/email/мессенджер-уведомлений: клиентская страница опрашивает статус раз в 30 секунд.
- Форма и корзина восстанавливаются из localStorage; выбранные файлы после перезагрузки браузера нужно приложить повторно, а согласие подтверждается заново. Удаление заявки вместе с фотографиями и смена пароля с отзывом всех сессий реализованы. Отдельное удаление одной фотографии, роли и автоматическое бонусное погашение не реализованы.
- Телефон/WhatsApp по умолчанию пусты; заглушка не выдаётся за реальный канал.
- Политика — юридическая заготовка, её нужно заполнить и согласовать.
- Локальный upload используется только в development; production требует приватный S3-compatible bucket. В development rate limit хранится в памяти; в production публичные POST-запросы требуют Upstash Redis и блокируются, если он не настроен. Настройте объектное хранилище и общий rate-limit.
- PWA manifest, SVG/PNG-иконки, service worker и offline route подготовлены; service worker кеширует только offline-страницу и статические ресурсы, приватные API/заказы/кабинет пропускает.

## Проверки

`npm run test` содержит unit-проверки расчёта и объединения позиций. В среде создания проекта проверка чистой функции расчёта выполнена отдельно: 6 сценариев пройдены. Полная установка пакетов, `prisma validate`, TypeScript typecheck, Next production build и end-to-end проверка не выполнены: доступ к npm registry в среде заблокирован DNS, база данных не настроена и браузерный прогон проекта не состоялся.
